# Rules

- Identify the choice, the evidence, and the effect on future work. Keep one-time directions with their task. For a temporary rule, record its scope, latest permitted use, and any early stop condition. A stated duration limits use even if the date of recovery is uncertain. Stop sooner if the early stop condition occurs. Ask before extending permission. Repeated rework or one serious failure can support a proposal.
- If the rule was absent or late, correct where or when the agent reads it. Check the work for compliance. If the work violates a clear rule in context, correct the work. Use an existing check if it can prevent the error.
- If corrections seem to conflict, check whether they apply under different conditions. Keep a reason if it changes how the agent applies the rule. Preserve permissions and exceptions. State if a new check adds to or replaces an existing check. Check the facts that make an alternative acceptable. Use the alternative only within project authority.
- Keep reusable decision patterns in `mentat`. Keep project decisions and facts in their project sources.
- Link to the code, configuration, or runbook that holds facts or procedures. State when to consult that source. Propose removal when a rule's purpose or condition no longer applies.

**Example.** The owner says to use a backup queue for two days. They say to return to the primary queue when it is healthy. Permit the backup for up to two days. Stop sooner if the primary queue recovers. Ask before use after two days.
